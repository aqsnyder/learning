# Security and Privacy

> **Why this section matters:** Bitcoin's security model is unique. Understanding attack vectors, privacy techniques, and self-custody best practices is essential.

**Prerequisites:** Sections [04 — Transactions and Script](../04-transactions-and-scripting/), [05 — Wallets and Key Management](../05-wallets-and-key-management/).

---

## 🎯 Learning Objectives

After this section you can:
- Build a threat model for a custody setup and justify its choices (single-sig vs multisig, passphrase, geographic distribution) with *Mastering Bitcoin* Ch. 13 and the guides linked from Lopp.net.
- Run a multi-device PSBT workflow (BIP 174) for a 2-of-3 multisig and explain what each role adds to the PSBT.
- Write Miniscript spending policies (e.g., a decaying multisig for inheritance) and reason about their witness costs and failure modes.
- Apply chain-analysis heuristics to a transaction graph and show exactly how CoinJoin and PayJoin break them.
- Explain hardware-signer attack classes — supply chain, fault injection, nonce exfiltration, address substitution — and the countermeasure for each.

## Suggested Order

**Core path (🔑):** Lopp.net: Bitcoin Security & Resources → *Mastering Bitcoin* Ch. 13 → BIP 174 (PSBT)

1. **Lopp.net: Bitcoin Security & Resources** — Survey the threat landscape; the page links the guides, attack catalogues and checklists the practices draw on.
2. **Mastering Bitcoin Ch. 13** — The security model and user practices in one chapter: cold storage, hardware signing devices, multisig and governance, inheritance.
3. **BIP 174: PSBT** — The signing workflow that makes multisig and cold storage practical (and BIP 370, its version 2).
4. **Bitcoin Core multisig and offline-signing tutorials** — Do it yourself on signet before trusting real funds to any setup.
5. **Optech: Exfiltration-resistant signing** — How a malicious signer can leak your seed, and the countermeasures.
6. **Optech: Coin selection** — How UTXO choices trade fees against privacy.
7. **Meiklejohn et al., "A Fistful of Bitcoins"** — How chain analysis clusters addresses: know what you're defending against.
8. **Bitcoin Wiki: Privacy** — Each chain-analysis heuristic and network-level attack in detail, with the countermeasure for each.
9. **Optech: Coinjoin and Payjoin** — Collaborative transactions, their known weaknesses, and the 2024 legal context.
10. **Bitcoin Privacy Guide** — Practical techniques to apply what you've learned.
11. **Antonopoulos, "How is Fungibility Tied to Privacy?"** — Why any of this matters for money.

## 🛠️ Practice

1. **Custody threat model** — Using *Mastering Bitcoin* Ch. 13 and the guides linked from Lopp.net, score three setups — phone single-sig; hardware single-sig + passphrase; 2-of-3 multisig across two hardware vendors and two locations — against malware and address substitution, supply-chain tampering, physical coercion, loss or fire, inheritance, and insider risk (likelihood × impact). Deliverable: a one-page matrix and a recommendation for one concrete scenario (e.g., a small company's treasury) that names the failure mode you are choosing to accept. *(~2 h · Lopp.net: Bitcoin Security & Resources; Mastering Bitcoin ch. 13)*
2. **Hardware-signer attack autopsy** — Pick two public attacks of different classes — e.g., fault-injection seed extraction from a general-purpose MCU, and malicious-firmware seed exfiltration through chosen signature nonces (the 2024 "Dark Skippy" disclosure) — and record for each: attacker access required, what leaked, root cause, and the countermeasure (secure element, anti-exfil signing, reproducible builds, on-device address verification). End with the list of countermeasures your section-01 and section-05 devices lack. *(~2 h · Lopp.net: Bitcoin Security & Resources (its timeline of hardware-wallet hacks); Bitcoin Optech: Exfiltration-resistant signing)*
3. **2-of-3 PSBT round trip** — Follow Bitcoin Core's `doc/multisig-tutorial.md` on signet (or adapt it to regtest), using the copy for the release you run: three signer wallets plus a watch-only coordinator holding a `wsh(sortedmulti(2,…))` descriptor. Walk creator → updater → signer → signer → combiner → finalizer → extractor (`walletcreatefundedpsbt`, `walletprocesspsbt`, `combinepsbt`, `finalizepsbt`, `sendrawtransaction`), saving the PSBT after each step. `decodepsbt` each one and list which PSBT fields appear at which role; hand-parse the magic bytes and first input map of one. Bitcoin Core 32.0 and later create version 2 PSBTs (BIP 370) by default: create one PSBT again with `psbt_version=0` and note which global and input fields differ. Make one signer an embit script to prove interoperability. *(~3 h · BIP 174: PSBT (and BIP 370); Bitcoin Core multisig and offline-signing tutorials; embit (Section 10))*
4. **Miniscript inheritance policy** — Write a policy such as `or(99@pk(Owner),and(thresh(2,pk(H1),pk(H2),pk(H3)),older(52560)))`, compile it with a Miniscript compiler (bitcoin.sipa.be/miniscript, rust-miniscript or BDK), and import the resulting `wsh(…)` descriptor into a Bitcoin Core regtest wallet — swap `older(52560)` for `older(20)` to test quickly. Spend via both branches, record each branch's witness size, and document what goes wrong if the owner forgets to move the coins before the heirs' timelock matures. *(~3 h · Mastering Bitcoin ch. 13 (multisig and governance, survivability); Lopp.net: Bitcoin Security & Resources (wallet backups); BIP 379: Miniscript (Section 05); Bitcoin Dev Kit (Section 10))*
5. **Chain-analysis lab** — Script three regtest "users" making ~50 transactions with realistic habits (address reuse, round payment amounts, change of a different script type, consolidations). Write an analyzer that applies common-input ownership plus two change-detection heuristics (pick them from the Bitcoin Wiki's Privacy article), and score its clustering against your ground truth. Then add one equal-output CoinJoin and one PayJoin-style transaction (the receiver contributes an input, as in BIP 78) and show exactly which heuristics each defeats. *(~4 h · Bitcoin Wiki: Privacy; Meiklejohn et al., "A Fistful of Bitcoins"; Bitcoin Optech: Coinjoin and Payjoin; Bitcoin Privacy Guide)*

**🏗️ Mini-project — Air-Gapped 2-of-3 on Signet:** Cosigners: a Bitcoin Core wallet, an offline embit script (a laptop or Raspberry Pi with networking disabled), and your section-05 microcontroller extended to sign PSBTs — or Specter-DIY on an STM32F469I-DISCO as a reference design. PSBTs move only by SD card, QR code or serial. The device must (1) recognise change outputs as belonging to the same 2-of-3 descriptor and refuse a PSBT whose "change" doesn't, (2) display destination, amount and fee before signing, and (3) sign with its BIP 32-derived key. Section 12's Lab 7 provides the hardware-in-the-loop test rig. Deliverable: `projects/btc/08-airgap-multisig/` with a runbook. Success: signet spends confirmed with every signer pair; a tampered-change PSBT from the coordinator is rejected on the device; a recovery drill rebuilds the wallet on a fresh machine from two seeds plus the descriptor backup. *(~14 h)*
