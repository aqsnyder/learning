# Schematic Capture and Library Management

> **Why this section matters:** Good schematics are the foundation of good boards.

**Prerequisites:** [Section 00 — Electronics Fundamentals](../00-electronics-fundamentals/README.md)

---

## 🎯 Learning Objectives

After this section you can:
- Design a library architecture — symbol ↔ footprint ↔ 3D linkage; MPN, manufacturer, alternates, DNP, and supplier fields; atomic vs generic parts — and justify it for small-batch production.
- Configure KiCad ERC (pin electrical types, power flags, pin-conflict matrix, no-connect discipline) so that a clean ERC carries real information and every waiver is documented.
- Verify vendor models from SnapEDA, Ultra Librarian, and SamacSys against the datasheet, catching pin-map, pin-type, polarity, and land-pattern errors before they reach a board.
- Structure a hierarchical schematic as a review document: page partitioning, net naming, and layout/test intent (Kelvin, guard, impedance, current, test points) captured on the sheet.
- Automate ERC, DRC, netlist, BOM, and PDF generation with `kicad-cli` in CI.

## Suggested Order

**Core path (🔑):** *Getting Started in KiCad* (KiCad 10) → Phil's Lab #165 (KiCad 9 schematic) → KiCad Library Conventions (KLC)

1. **Getting Started in KiCad** — Walk through the official tutorial to learn the EDA environment.
2. **KiCad project templates** — Build your own project template (title block, board setup, design rules, fab-note layers) so every new project starts consistently.
3. **Phil's Lab #165** — Watch a complete schematic captured from start to finish.
4. **SnapEDA / Ultra Librarian / SamacSys** — Learn to pull symbols and footprints instead of drawing from scratch, but always check pin maps and land patterns against the datasheet before first use.
5. **KiCad Library Conventions (KLC)** — Use as the style guide for your own symbol and footprint libraries.
6. **KiCad Schematic Editor manual** — Read the ERC, power-symbol and label chapters before Practice 2.
7. **AN4488 (or your STM32 family's equivalent)** — Run every MCU schematic against it: power pins, decoupling, reset, clocks, boot and debug.
8. **Feranec's schematic series and *10 Tips*** — Study common mistakes and the checks an experienced reviewer makes.

## 🛠️ Practice

1. **Vendor-model audit** — Download the SnapEDA, Ultra Librarian, and SamacSys models for three parts you actually use: an STM32U5 in LQFP, a 16-pin USB-C receptacle, and an RJ45 with integrated magnetics. Check each against the datasheet: pin numbers and names, electrical types (power pins typed as power input? NC pins truly unconnected?), pads vs the manufacturer's recommended land pattern, courtyard, pin-1/polarity marking, paste layer, mechanical holes and shield tabs, and 3D-model alignment. Deliverable: defect table (vendor × part × defect × severity). Done when every defect is proven by overlaying the datasheet drawing in the footprint editor and measuring. *(~3 h · SnapEDA, Ultra Librarian, SamacSys, KiCad Library Conventions (KLC))*
2. **ERC that means something** — On one of your real schematics, retype pins so supply nets are driven by `power output` pins (regulator outputs) instead of blanket `PWR_FLAG`s, set the pin-conflict matrix deliberately, run ERC, and justify every exclusion in one line. Then seed six faults — floating VDDA, missing I²C pull-ups, a label typo (`SDA` vs `SDA1`), two regulator outputs tied together, an unconnected hierarchical sheet pin, swapped crystal pins — and record which ones ERC catches. Deliverable: before/after ERC reports, the waiver list, and how you would catch each miss (single-label-net warning, a netlist script, a review checklist). *(~2.5 h · Getting Started in KiCad, KiCad Schematic Editor manual (ERC, power symbols), Phil's Lab #165)*
3. **Feranec's checklist, applied** — Watch two of Robert Feranec's schematic videos (the *How to Draw Schematic* parts or *10 Tips for Better Schematic Checking*) and distill his recurring checks into a ≥ 25-item checklist (power-up, reset and boot pins; decoupling per datasheet; crystal load caps; ESD/TVS on every external connector; pull-ups/downs and strap pins; debug access; test points; current and voltage ratings). Apply it to your latest STM32U5 schematic — e.g., recompute the HSE load caps as C1 = C2 = 2(C_L − C_stray) and confirm CC1 and CC2 each have their own 5.1 kΩ Rd. Deliverable: checklist + findings ranked blocker/major/minor. Done when you have ≥ 3 actionable findings, or a written argument for every item you pass. *(~3 h · Feranec's How to Draw Schematic series and 10 Tips, Phil's Lab #165, AN4488)*
4. **Schematic CI** — Add a GitHub Actions workflow to a KiCad project repository of your own (ideally one started from your project template), using the official KiCad Docker image, that runs `kicad-cli sch erc --exit-code-violations` and `kicad-cli pcb drc --exit-code-violations`, exports netlist, BOM CSV, and schematic PDF as artifacts (or runs a KiCad 9+ jobset via `kicad-cli jobset run`), and posts a BOM diff against the previous commit to the job summary. Deliverable: working workflow. Done when a deliberately broken commit fails with the violation in the log and a clean commit passes. *(~3 h · kicad-cli manual (Section 09), KiCad project templates)*

**🏗️ Mini-project — Library QA Bot:** Write a Python linter for your personal KiCad library — parse the `.kicad_sym` / `.kicad_mod` S-expressions directly, or extend KiCad's own KLC checker scripts (kicad-library-utils). Checks: every symbol has MPN, manufacturer, datasheet URL, and a footprint that resolves; IC symbols are not all `passive` pins; footprints have courtyard, fab, and silk layers, a pin-1 marker, paste apertures within a sane fraction of pad area, and a 3D model that resolves. Run it in CI beside Exercise 4. Deliverable: `projects/pcb/02-libqa/` plus the CI job. Success: a full-library run in < 60 s, zero false positives on 10 hand-verified parts, and it flags the vendor-model defects you found in Exercise 1. *(~10 h)*
